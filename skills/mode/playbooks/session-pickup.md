### Session pickup

**You own the resume point. Read the prior trail, don't redo it.**

1. Locate the prior trail through current context, the supplied handoff, or available list/read chat tools scoped to the requested project, topic, and time. Read recent summaries first, then retrieve relevant older turns. A supplied artifact or pushed branch is also evidence. Do not invent transcript paths. Summaries omit tool-level detail; state gaps. Delegate long supplied artifacts when useful. Do not message another chat without user authorization.
2. Read [Execution state](../references/execution-state.md). Inspect the active provider’s goal state when present or relevant, reconcile it with the saved plan, and never replace an unfinished Goal or invent a resume call. Link an existing PR when it is the requested work target and use the provider’s attachment capability when available. Reconstruct operational state. The branch and worktree, what already landed (`git log`, `git diff` against the base), the open todos, the decisions made. Treat the prior trail as evidence to reconcile with current artifacts. Resist the bias to re-derive it.
3. Diff done vs pending. Compare what shipped against what was planned, name the resume point, reuse recorded proof when its revision, environment, and artifacts still apply. Rerun only stale, missing, or uncertain evidence and explain why.
4. Route the remaining work to the matching playbook and pick the verdict: continue the execution, ship a finished recommendation, ratify or override a prior conclusion, or postmortem a failed run. The pickup playbook ends here. The routed playbook owns the rest.
5. Verify the inherited claims on the real artifact against the reconciled plan, including amendments from the user and authorized handoffs (the **principle-prove-it-works** skill). A passing prior self-report is not the proof.

**Reply:** where the prior agent stopped, what you inherited vs redid (ideally nothing redone), the resume point, and the outcome.
