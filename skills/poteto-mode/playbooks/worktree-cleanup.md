### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`, then run `scripts/worktree-audit.sh [-b <base-ref>] [repo-path]`. This read-only script inspects git worktrees and local refs. It never fetches, reads chat history, or marks a tree safe to delete. Supply the actual target base when remote HEAD is not the PR base. A stale local ref is incomplete evidence.
2. Reconcile ownership with Codex `list_artifacts`, `list_threads`, and relevant scoped chat reads. Pinned, active, primary, shared, and delegated worktrees are held. A clean git status does not establish that no process or agent is using a tree. Chat summaries do not prove absence of work. If ownership remains unknown, hold the tree and report why.
3. Inspect each candidate’s tracked, untracked, and ignored files, local-only commits, and PR state. Untracked files are user work until shown otherwise. Preserve needed ignored files separately. Never label all untracked files disposable scratch. Read-only delegates may inspect disjoint candidates, returning exact paths and evidence.
4. Archive confirmed unused managed worktrees with the Codex archive-worktree tool using the exact identity returned by list_artifacts. The tool preserves a recoverable snapshot of commits and non-ignored changes. Do not bypass its exclusions or remove managed paths manually. Archive only within the user’s cleanup authorization.
5. For ordinary unmanaged worktrees, remove only confirmed unused, clean, merged candidates with `git worktree remove <exact-path>` after establishing authorization. Do not force removal or recursively delete remaining directories. Preserve or ask about valuable uncommitted and ignored files. Re-list worktrees and record `df -h /` afterward.
6. Simulators and caches are separate cleanup targets. Inspect `xcrun simctl list` and runtime usage first. Delete only the specific stale simulators, runtimes, or caches covered by the request after checking no active task needs them. Do not clear application state or chat history as a disk-space shortcut.

**Reply:** disk usage before and after, archived or removed worktrees, preserved artifacts, and the evidence for each held candidate.
